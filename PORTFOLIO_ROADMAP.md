## Standard for every repository

Each project should include as many of the following as are genuinely relevant:

- clear problem statement
- architecture or workflow diagram
- implementation guide
- reproducible code or configuration
- synthetic or sanitised sample data
- tests or validation
- runbook or operating procedure
- security considerations
- monitoring / logging approach
- evidence of outcomes where appropriate
- lessons learned
- future improvements
- explicit provenance note where work is reconstructed

## Evidence standard

No repository should imply that recreated evidence is original historical material.

Real professional work may be represented using sanitised reconstructions, representative data and rewritten documentation. These should be labelled clearly. Employer-confidential information, production data, internal screenshots, credentials, tenant details and sensitive incident evidence are excluded.
